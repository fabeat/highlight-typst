// Regression test for `$ ... $` wrapped in inline-code
// backticks. Before the fix, the inline-math begin regex
// was `(?<!\w)\$\S` - "$" not preceded by a word char,
// followed by ANY non-whitespace char. In `` `$ ... $` ``,
// the first "$" is followed by a space (begin does not
// match - correct), but the second "$" is followed by a
// backtick (non-whitespace, so begin matched), opening a
// math span that never closed and swallowing the rest of
// the document in `hljs-meta`. The fix adds the backtick
// to both the lookbehind (so a "$" preceded by a backtick
// does not start math) and the lookahead (so a "$" followed
// by a backtick does not start math either). This file
// is the user-reported showcase line, plus a handful of
// variations to lock the new behaviour in.

// The exact line from `spora-plugin-typst/skills/typst/examples/showcase.typ`.
*Bold text*, _italic text_, `inline code`, and inline math
delimiters (the `$ ... $` pair — see section 7).

// Other shapes that previously misbehaved the same way.
Bare: `$ ... $`.

Math inside an inline-code span: `` `$x$` `` and `` `$ ... $` ``.

Display-math-like text inside backticks is also left alone
because `$ ` is whitespace after, not math start: `` `$ x^2 $` ``.

A real inline-math next to an inline-code span still highlights
as math when the `$` is not at a backtick boundary: $x$ and `` `$y$` ``.
